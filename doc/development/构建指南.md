### 2.1 代码合规检查工具(clang-format + 软链)

代码风格合规检查(见 `脚手架搭建规范.md` §6.1)依赖 `clang-format`。安装,并处理一处 Ubuntu 打包差异:

```bash
# 安装 clang-format(Ubuntu/Debian)
sudo apt install clang-format
```

Zephyr 的 `check_compliance.py` 的 ClangFormat 检查**写死**调用 `clang-format-diff.py`(带 `.py`),而 Ubuntu 打包名为 `clang-format-diff`(无 `.py`)。补一个用户级软链(无需 sudo,`~/.local/bin` 已在 PATH):

```bash
# /usr/bin/clang-format-diff 本身就是 LLVM 的 clang-format-diff.py,仅名字少了后缀
ln -sf /usr/bin/clang-format-diff ~/.local/bin/clang-format-diff.py
which clang-format-diff.py   # 应输出 ~/.local/bin/clang-format-diff.py
```

> CI(GitHub Actions)若使用 Zephyr 官方构建镜像,`clang-format-diff.py` 原生自带,无需软链;本步骤仅针对本地 Ubuntu/WSL 开发机。缺此软链时 ClangFormat 检查会报找不到可执行文件,Checkpatch 不受影响。

## 3. 激活环境

`west` 装在 `.venv` 里,构建前先激活虚拟环境:

```bash
cd ~/Workspace/Zephyr-Workspace
source .venv/bin/activate
```

> `activate` 必须用 `source`(或 `.`)读入当前 shell,**不能**直接 `./activate` 运行——它需要修改当前 shell 的 `PATH`/`VIRTUAL_ENV`,直接执行只影响子进程且会因无执行位报 `Permission denied`。

激活后提示符出现 `(.venv)` 前缀,此时可直接用 `west`,无需写 `.venv/bin/west` 全路径。退出用 `deactivate`。

如需临时不激活,可用全路径:`.venv/bin/west build ...`。

## 4. 构建

### 4.1 增量构建

```bash
west build -b art_pi2 bms-app/app -d build
```

- `-b art_pi2`:目标板
- `bms-app/app`:应用源码目录(含 `CMakeLists.txt` / `prj.conf`)
- `-d build`:输出目录

首次构建后,再次执行会增量编译;修改 `prj.conf` 或 devicetree 后建议 pristine 重建。

### 4.2 pristine(全新)构建

改动配置、切换板卡或 CMake 缓存异常时,用 `-p always` 清空重建:

```bash
west build -b art_pi2 bms-app/app -d build -p always
```

### 4.3 预期产物

构建成功后在 `build/zephyr/` 生成:

| 文件 | 用途 |
| --- | --- |
| `zephyr.elf` | 调试用(含符号) |
| `zephyr.hex` | 烧录用(带地址信息) |
| `zephyr.bin` | 烧录用(裸二进制) |

构建结束会打印各内存区(FLASH/RAM 等)的占用与占比,以此关注体量。

> FLASH 仅 64 KB,是本板内部 Flash 的硬约束。新增功能时留意 `prj.conf` 不要引入大体量子系统,必要时评估外部 Flash / XIP。

## 5. WSL2 下连接调试探针(usbipd + udev)

开发环境是 **WSL2**,而 WSL2 默认**不透传任何 USB 设备**。板载 ST-Link 插在 Windows 上,必须先用 `usbipd-win` 把它转发进 WSL,再配 udev 规则让 pyOCD 免 sudo 访问。不做这两步,`pyocd list` 只会显示 `No available debug probes are connected`。

### 5.1 Windows 侧:安装 usbipd-win(一次性)

在 **Windows PowerShell(管理员)** 执行,装完重开一个 PowerShell 窗口:

```powershell
winget install --interactive --exact dorssel.usbipd-win
```

### 5.2 Windows 侧:绑定 ST-Link(一次性)

插好 ART-Pi2 的 ST-Link 口后列出设备,找到 `STMicroelectronics STLink`(VID:PID `0483:374b`)那一行,记下 `BUSID`:

```powershell
usbipd list
```

绑定(共享给 WSL,重启后仍有效;`Persisted` 段出现记录即已绑定):

```powershell
usbipd bind --busid <BUSID>
```

绑定成功后该设备在 `usbipd list` 的 `Connected` 段 STATE 显示 `Shared`。

### 5.3 Windows 侧:附加到 WSL(每次插拔/重启后都要做)

```powershell
usbipd attach --wsl --busid <BUSID>
```

成功输出会包含 `Loading vhci_hcd module`,STATE 变为 `Attached`。若嫌每次手动附加麻烦,用自动附加(命令挂前台监听,插上即接入):

```powershell
usbipd attach --wsl --busid <BUSID> --auto-attach
```

> 若报 `WSL is not running`,先在 WSL 终端里随便跑一条命令唤醒发行版再重试;多发行版用 `--distribution <名字>` 指定(名字见 `wsl -l -v`)。

### 5.4 WSL 侧:配置 udev 免 sudo 规则(一次性)

设备转发进来后,`/dev/bus/usb/...` 节点默认属 `root:root`、其他用户只读,pyOCD(非 root)无法读写打开,`pyocd list` 仍为空。加一条 udev 规则,把 ST-Link 交给 `plugdev` 组(当前用户已在该组):

```bash
sudo tee /etc/udev/rules.d/49-stlink.rules >/dev/null <<'EOF'
# STMicroelectronics ST-LINK V2 / V2-1 / V3 — 允许 plugdev 组免 sudo 访问
SUBSYSTEM=="usb", ATTR{idVendor}=="0483", ATTR{idProduct}=="3744", MODE="0660", GROUP="plugdev", TAG+="uaccess"
SUBSYSTEM=="usb", ATTR{idVendor}=="0483", ATTR{idProduct}=="3748", MODE="0660", GROUP="plugdev", TAG+="uaccess"
SUBSYSTEM=="usb", ATTR{idVendor}=="0483", ATTR{idProduct}=="374b", MODE="0660", GROUP="plugdev", TAG+="uaccess"
SUBSYSTEM=="usb", ATTR{idVendor}=="0483", ATTR{idProduct}=="374d", MODE="0660", GROUP="plugdev", TAG+="uaccess"
SUBSYSTEM=="usb", ATTR{idVendor}=="0483", ATTR{idProduct}=="374e", MODE="0660", GROUP="plugdev", TAG+="uaccess"
SUBSYSTEM=="usb", ATTR{idVendor}=="0483", ATTR{idProduct}=="374f", MODE="0660", GROUP="plugdev", TAG+="uaccess"
# ST-LINK 虚拟串口(CDC-ACM / VCP)—— 同样交给 plugdev 组,供串口控制台免 sudo 打开
SUBSYSTEM=="tty", ATTRS{idVendor}=="0483", ATTRS{idProduct}=="3748", MODE="0660", GROUP="plugdev", TAG+="uaccess"
SUBSYSTEM=="tty", ATTRS{idVendor}=="0483", ATTRS{idProduct}=="374b", MODE="0660", GROUP="plugdev", TAG+="uaccess"
SUBSYSTEM=="tty", ATTRS{idVendor}=="0483", ATTRS{idProduct}=="374e", MODE="0660", GROUP="plugdev", TAG+="uaccess"
SUBSYSTEM=="tty", ATTRS{idVendor}=="0483", ATTRS{idProduct}=="374f", MODE="0660", GROUP="plugdev", TAG+="uaccess"
EOF
sudo udevadm control --reload
sudo udevadm trigger
```

> WSL2 需启用 systemd(`/etc/wsl.conf` 里 `[boot] systemd=true`)才会运行 udevd,规则才能在热插拔时自动生效。改完 `wsl.conf` 需在 Windows 执行 `wsl --shutdown` 后重进。规则加好后,重新执行 5.3 的 `attach`(或重载+trigger)让新权限套到设备上。

### 5.5 WSL 侧:验证

```bash
cd ~/Workspace/Zephyr-Workspace && source .venv/bin/activate
pyocd list
```

应列出一行 STLink 探针、target 类似 `stm32h7r7l8hxh`。到此探针就绪,可进入第 6 节烧录。

### 5.6 串口控制台(查看 printk 输出)

ST-Link 同时提供一个虚拟串口(VCP),Zephyr 控制台默认走它,波特率 **115200**。设备节点为 `/dev/ttyACM0`,默认属组 `dialout`,而当前用户不在该组——两种放行方式任选:

- **已随 §5.4 解决**:上面的 udev 规则已把该 `tty` 交给 `plugdev` 组(当前用户已在组内),`reload` + 重新 `attach` 后即可免 sudo 打开,无需重启 WSL。
- **标准做法**:`sudo usermod -aG dialout $USER`,然后 `wsl --shutdown`(Windows 侧)重进使组生效。

打开串口查看输出(任选其一):

```bash
# VS Code「Serial Monitor」扩展:端口 /dev/ttyACM0,波特率 115200
# 或命令行:
picocom -b 115200 /dev/ttyACM0      # 退出 Ctrl+A Ctrl+X
# 或:
python -m serial.tools.miniterm /dev/ttyACM0 115200
```

复位板子(`pyocd reset --target stm32h7r7l8hxh`)后应看到开机横幅:

```text
*** Booting Zephyr OS build v4.4.0 ***
BMS blinky start on ART-Pi2
```

## 6. 烧录

板卡支持两个 runner,均需先完成第 5 节的 USB 转发与 udev 配置。

### 6.1 pyOCD

```bash
west flash -r pyocd -d build
```

pyOCD 采用差分烧录:若片上内容与镜像一致会跳过擦写(日志显示 `skipped ... pages`),属正常。

### 6.2 STM32CubeProgrammer(board.cmake 默认 runner)

ST 官方工具,`board.cmake` 里的默认 runner。需先安装 STM32CubeProgrammer(见 §2 前置环境)并把其 `bin/` 加入 PATH:

```bash
# ~/.bashrc 中加入(安装路径按实际):
export PATH="$HOME/STMicroelectronics/STM32Cube/STM32CubeProgrammer/bin:$PATH"
```

然后用**默认 runner**(不带 `-r`)即可:

```bash
west flash -d build
```

成功日志包含 `File download complete` 与 `Start operation achieved successfully`。单独连板自检可用 `STM32_Programmer_CLI -c port=SWD mode=UR`。

> 二者取一即可。USB 权限报错时:确认在 `plugdev` 组(`id | grep plugdev`)、udev 已 `reload`,并重新 `attach` 一次让权限生效。

## 9. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `source .venv/bin/activate` 报 `Permission denied` | 直接执行了 activate,而非 source | 用 `source` / `.` 前缀 |
| `west` 命令找不到 | 未激活 venv 或 `~/.local/bin` 不在 PATH | `source .venv/bin/activate` |
| west 找不到 manifest | `.west/config` 的 `manifest.path` 指向错误目录 | 应指向 `bms-manifest`,见 §1 拓扑 |
| 构建报找不到工具链 | 未检测到 Zephyr SDK | 确认 `~/zephyr-sdk-*` 存在,或设 `ZEPHYR_TOOLCHAIN_VARIANT`/`ZEPHYR_SDK_INSTALL_DIR` |
| `pyocd list` 显示 `No available debug probes` | WSL 未 attach,或已 attach 但缺 udev 权限 | 依次查:§5.3 `usbipd attach` 是否做过;§5.4 udev 规则是否已加并 reload |
| WSL 里 `lsusb`/sysfs 看不到 `0483` | Windows 侧未 `usbipd attach --wsl` | 每次插拔/重启后重跑 §5.3 |
| 探针可见但烧录报权限错误 | udev 规则未生效 | 确认在 `plugdev` 组、`udevadm control --reload` 后重新 attach |
| 无法打开串口 `/dev/ttyACM0` | 用户不在 `dialout` 组,且串口无 plugdev 规则 | 见 §5.6:用 udev 划给 `plugdev`,或加入 `dialout` 组后重启 WSL |
